# Wave 0 baseline against encoding_rs, 2026-11-02

Where wave 0 stands against encoding_rs 0.8.44, and the comparison arms,
on UTF-8, UTF-16LE/BE, x-user-defined, and the 28 single-byte encodings.
The numbers are from a shared 4-vCPU orb, not dedicated hardware: read the
ratios, not the absolute GB/s.

Headline: geomean 1.12x encoding_rs over 1736 rows (zig GB/s divided by
encoding_rs's, per row, paired by round); single-byte tables 6912 bytes
of .rodata in both; peak RSS 32 MiB against 33–35 MiB. Over the 28
single-byte encodings, geomean against encoding_rs: decode to UTF-8 1.00x
(0.87 GB/s), decode to UTF-16 1.02x (1.42 GB/s), encode from UTF-8 0.93x
(0.31 GB/s), encode from UTF-16 1.77x (1.08 GB/s). UTF-8 decode 1.16x to
UTF-8 and 1.89x to UTF-16; UTF-16LE/BE decode 1.3–2.4x.

## Machine and method

Intel(R) Xeon(R) Processor @ 2.60GHz, 4 vCPUs, AVX-512 (f, bw, cd, dq,
vl, vbmi, ifma), Linux 6.1. Zig 0.16 ReleaseFast for the host CPU;
encoding_rs 0.8.44 for Rust's default x86-64 target (its own SSE2 code;
its `simd-accel` feature needs nightly Rust), release with LTO; ICU 78.3, glibc iconv,
GNU libiconv, and golang.org/x/text v0.43.0 from the dev shell.

`BENCHTIME_MS=20 just arms="rust zig" bench-compare 10 '(web|nonascii|invalid)-(16|64|256|4096|1048576)$'`:
the web page, non-ASCII-only, and random-bytes shapes at five sizes, every
operation, every encoding both arms have; ten rounds, each arm a server
pinned to the last core, the two arms back to back on each row in rotating
order (bench/README.md has the method). Above 1, this package is faster.

## Table size and memory

`just bench-rodata` finds each single-byte table's 128 code points in the
two arm binaries. encoding_rs stores the same 27 distinct tables the same
way (ISO-8859-8-I shares ISO-8859-8's), 128 `u16` each; its label table
adds `LABELS_SORTED` (3648 bytes) and `ENCODINGS_IN_LABEL_SORT` (1824
bytes) of pointers, where this package's generated label table is
one sorted array of label slices and tags.

## Gaps for wave 2

- Short decodes into UTF-8: `web-16` is about 0.6x on every single-byte
  encoding. The input is all ASCII, so this is fixed cost: `Decoder.init`
  is an out-of-line call that returns the family union, and `decode`
  dispatches through it, with options read from memory.
- Encoding to the non-Latin single-byte encodings (ISO-8859-5/6/7/8,
  windows-1251/1253/1255, KOI8, x-mac-cyrillic) on non-ASCII text:
  0.1–0.5x. The run arithmetic covers the alphabet, but the loop pays
  `readScalar`, the run check, and a room check per character and returns
  to the ASCII scan every 16 units; encoding_rs runs a tight loop while
  the input stays in the run.
- x-user-defined: 0.1–0.6x; it has no fast path at all yet.
- UTF-8 to UTF-8 "encode" is 0.35x because encoding_rs takes a validated
  `&str` and copies it, where this package validates bytes; not the same
  work.
- UTF-16LE/BE decode to UTF-8 on `web-16`: about 0.5x, and UTF-8 decode
  on `web-16` 0.6–1.0x from run to run: the same fixed cost as above.
