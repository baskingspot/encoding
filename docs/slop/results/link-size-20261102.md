# What a program links: decode-only, encode-only, one encoding

Question from the owner: does a program that only decodes still link the
CJK encode tables (rank tables, 158 KB for gb18030, Big5, euc_kr, and
jis0208), which make our encoders 4-19x encoding_rs?

Main at `c655483`, Zig 0.16.0, x86_64-linux. Five scratch programs, each
reading stdin and writing stdout through the public API:

- `none`: copies stdin to stdout; no encoding import.
- `decode1252`: `Decoder.init(.windows_1252, .{})`, comptime-known.
- `decode`: `Encoding.forLabel(argv[1])`, then `Decoder.decodeToUtf8`.
- `encode`: `Encoding.forLabel(argv[1])`, then `Encoder.encodeFromUtf8`.
- `both`: decode, then encode the result.

| program    | .rodata added |

| decode1252 |       178,148 |

Findings:

1. A program that never references `Encoder` does not link the encode
   tables: `both` minus `decode` is 158,664 bytes, the rank encode tables'
   size. The 96 KB of Chinese encode tables, and Korean's 42 KB, cost only
   programs that encode, which are the ones that gain the speed.
2. A program that decodes one known single-byte encoding still links every
   decode table (178 KB), because `Decoder` dispatches on a runtime tag
   over every family even when `init`'s argument is comptime-known.
   encoding_rs has the same property (its `Encoding` dispatches at run
   time too), but Zig could avoid it with a comptime-specialized decoder.
   Not measured or designed yet.
